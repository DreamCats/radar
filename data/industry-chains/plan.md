# 产业链学习页落地规划

本文沉淀“产业链”Tab 的产品和技术方案。

本文属于产业链内容库资产，当前放在：

```text
data/industry-chains/plan.md
```

具体产业链页面放在：

```text
data/industry-chains/chains/
```

当前判断：

```text
不要第一阶段做全自动产业链知识图谱。
先做“统一结构 + 定制内容”的产业链学习内容库。
内容生产主要靠 Codex 调研和编辑，不靠离线任务自动生成。
```

也就是：

- 80% 页面结构固定。
- 20% 产业内容定制。
- 图谱数据结构统一。
- 视觉组件统一。
- 每个产业允许插入少量自定义图块。
- 后续再接入消息系统和 AI 抽屉。
- 产业内容由 Codex 逐个调研、整理、校验和更新。

## 为什么不先做自动图谱

理想状态里的产业链图谱很有价值，但全自动落地难度高。

难点不在前端画图，而在：

- 每个行业的链条颗粒度主观性很强。
- A 股公司经常跨业务，单一行业标签不等于真实受益路径。
- 公司是否受益必须看主营、收入占比、客户、订单、产能、认证和现金流。
- 公开概念板块、行业分类、市场热度只能说明“相关”，不能说明“真受益”。
- 技术变革会改变产业链卡点，需要持续维护。

所以第一阶段不追求：

```text
输入任意股票 -> 自动生成可信产业链真相图谱
```

第一阶段追求：

```text
用户打开某个产业页 -> 能快速看懂这个产业怎么运转、卡点在哪、A 股公司分别处在哪些节点、哪些关系已经验证、哪些只是候选。
```

## 产品定位

Tab 名建议先用：

```text
产业链
```

它比“行业学习”更直接，也更符合最终形态。

它不是策略推荐页，不输出买卖建议。

它解决三个问题：

1. 小白快速看懂一个产业。
2. 投研时快速定位产业链卡点和 A 股映射。
3. 后续消息系统和 AI Agent 有一个稳定挂载点。

## 第一阶段边界

第一阶段要做：

- 产业链列表。
- 单个产业详情页。
- 标准化产业链图谱。
- 产业节点详情。
- 公司角色分层。
- 小白解释卡。
- 常见误区和验证清单。
- 内容文件驱动，先不依赖消息系统。

第一阶段不做：

- 自动生成全市场产业链。
- 自动判断所有股票是否真受益。
- 实时更新产业链关系。
- 复杂图数据库。
- 消息系统自动挂载到节点。
- AI Agent 自动改内容。
- 爬虫、调度器、批量离线生产任务。

这些能力保留接口，但不作为 P0。

## 页面信息架构

每个产业页统一使用这套结构：

```text
产业一句话
  -> 这个产业解决什么问题
  -> 为什么现在重要
  -> 一张核心链路图
  -> 关键卡点
  -> 节点详情
  -> A 股公司分层
  -> 常见误区
  -> 跟踪指标
  -> 证据来源
```

推荐首屏：

```text
左侧：产业目录 / 搜索
中间：产业链图谱
右侧：当前节点详情
底部：A 股公司角色表
```

首屏不要铺满所有内容。

默认只展示 5 到 12 个关键节点，让用户先建立框架。

## 小白模式

每个产业页必须回答 5 个问题：

1. 谁在买？
2. 为什么现在变重要？
3. 卡点在哪里？
4. 谁能真正收钱？
5. 什么情况说明逻辑错了？

这 5 个问题比完整百科更重要。

原因是小白真正缺的不是材料，而是判断框架。

## 研究员模式

研究员模式展示更细的证据和风险：

- 产业链节点。
- 供需约束。
- 技术壁垒。
- 替代路线。
- 国产替代难点。
- 公司角色。
- 收入占比。
- 客户和订单。
- 产能和认证。
- 价格、交期、招标、政策等跟踪指标。
- 证据状态。
- 失效条件。

研究员模式不需要第一阶段做完整。

但数据结构要提前兼容。

## 内容组织方式

不要做 100 个完全手写页面。

推荐做：

```text
统一渲染组件 + 每个产业一份内容数据
```

内容可以先放在仓库里，使用 Markdown / MDX / JSON / YAML 都可以。

建议第一版用：

```text
docs 或 data 下的产业内容文件
```

后续如果要给 AI Agent 修改内容，再迁移到数据库或受控 CMS。

## 内容生产原则

这里的“产业链内容库”不是一个自动化数据平台。

第一阶段的内容生产方式是：

```text
Codex 作为研究员和编辑
  -> 上网查公开资料、公告、年报、互动问答、产业文章和市场讨论
  -> 提炼产业链结构、关键节点、技术瓶颈、A 股映射和误判风险
  -> 按统一 schema 写入内容文件
  -> 用户审阅后继续打磨
```

系统本身只做三件事：

- 渲染统一页面。
- 约束内容结构。
- 保留后续扩展入口。

系统不负责：

- 自动爬取全网。
- 自动批量生成产业链。
- 自动判断公司受益程度。
- 自动把市场新消息写进产业页。

这样做的核心原因是：

```text
大多数成熟产业链的底层结构变化不频繁。
真正值得投入的是把少数高质量页面打磨准确，而不是提前建设复杂自动化。
```

后续如果产业链出现变化，也优先由 Codex 针对变化部分做增量更新：

- 新技术路线出现。
- 新瓶颈变重要。
- 某个公司从候选变成有证据支持。
- 某个旧逻辑被证伪。
- 某个节点需要补充新图块。

这是一套“人工主导、AI 辅助、结构化沉淀”的流程。

## 数据结构草案

### industry_chains

产业页主信息。

| 字段 | 含义 |
| --- | --- |
| chain_id | 稳定 ID，例如 `ai-liquid-cooling` |
| title | 页面标题，例如 `AI 算力液冷` |
| aliases | 别名和相关主题 |
| category | 大类，例如 `AI 硬件` |
| summary | 一句话解释 |
| why_now | 为什么现在重要 |
| status | draft / active / archived |
| updated_at | 更新时间 |

### chain_nodes

产业链节点。

| 字段 | 含义 |
| --- | --- |
| node_id | 节点 ID |
| chain_id | 所属产业链 |
| title | 节点名 |
| layer | upstream / midstream / downstream / application / signal |
| role | demand / component / material / equipment / process / service / company |
| beginner_explain | 小白解释 |
| technical_difficulty | 技术难点 |
| bottleneck_score | 卡点强度，0 到 5 |
| evidence_status | candidate / supported / weakly_supported / unsupported |
| sort_order | 展示顺序 |

### chain_edges

节点之间的关系。

| 字段 | 含义 |
| --- | --- |
| edge_id | 关系 ID |
| chain_id | 所属产业链 |
| source_node_id | 起点 |
| target_node_id | 终点 |
| relation_type | demand_pull / cost_pass / supply_constraint / substitute / validation |
| label | 页面上的关系文案 |
| explain | 关系解释 |
| evidence_status | candidate / supported / weakly_supported / unsupported |

### stock_chain_roles

A 股公司在产业链里的位置。

| 字段 | 含义 |
| --- | --- |
| chain_id | 所属产业链 |
| node_id | 对应节点 |
| ts_code | 股票代码 |
| stock_name | 股票名 |
| role_label | 真瓶颈 / 验证节点 / 二阶受益 / 待验证 / 蹭概念风险 |
| directness | direct / indirect / theme / weak |
| business_exposure | 相关业务描述 |
| revenue_share | 收入占比；不知道就留空 |
| evidence_status | candidate / supported / weakly_supported / unsupported |
| evidence_refs | 证据引用 |
| next_check | 下一步验证 |

### custom_blocks

每个产业允许插入少量自定义图块。

| 字段 | 含义 |
| --- | --- |
| block_id | 图块 ID |
| chain_id | 所属产业链 |
| block_type | markdown / metric_strip / image / comparison / timeline / mini_graph |
| title | 标题 |
| payload | 内容 |
| sort_order | 展示顺序 |

这能保证：

- 80% 结构统一。
- 20% 内容可以定制。
- 不会变成 100 个难维护的页面。

## 视觉组件

第一阶段只需要这些组件：

- 产业链目录。
- 搜索框。
- 产业页标题区。
- 小白 5 问。
- 产业链图谱。
- 节点详情抽屉。
- 公司角色表。
- 自定义内容块。
- 证据来源列表。

产业链图谱建议用 React Flow / xyflow。

理由：

- 节点和边模型贴合产业链。
- 自定义节点样式容易。
- 右侧详情抽屉容易联动。
- 第一版只做小图，不需要复杂图算法。

暂时不建议第一阶段上 AntV G6 或 Cytoscape。

它们适合更复杂的大图分析，但第一阶段会增加心智负担。

## AI 抽屉的预留位置

后续可以在产业页右侧或底部加一个 AI 抽屉。

AI 抽屉可以做三类事：

1. 问答：解释当前节点、公司、卡点。
2. 证据补全：提示缺少哪些年报、公告、IR 或订单证据。
3. 内容编辑：让 AI Agent 帮忙修改产业页内容。

第一阶段只需要预留数据边界，不实现编辑。

后续如果做编辑工具，必须满足：

- 只改结构化内容文件或数据库记录。
- 每次修改生成 diff。
- 修改必须保留证据引用。
- 不能把 `candidate` 自动升级为 `supported`。
- 不能输出买卖建议。

## 和消息系统的关系

第一阶段不接消息系统。

后续可以这样接：

```text
微信消息 / 研报 / 公告
  -> 识别产业主题
  -> 匹配 chain_id
  -> 匹配 node_id
  -> 作为 dynamic_signal 挂到产业页
```

例如：

```text
液冷散热新动向
  -> AI 算力液冷
  -> 液冷系统 / 冷板 / CDU 节点
  -> 新增一条动态变化
```

这样消息系统不是第一阶段依赖，而是后续增强。

## 推荐 P0 样板产业

不要一口气做 100 个。

先做 5 到 10 个样板产业，验证页面结构和内容生产流程。

推荐第一批：

1. AI 算力液冷
2. CPO/光通信
3. PCB/先进封装
4. 半导体设备
5. 半导体材料
6. 机器人
7. 固态电池
8. 低空经济
9. 创新药
10. 消费电子

选择标准：

- 当前市场讨论多。
- A 股映射多。
- 容易出现“真瓶颈 vs 蹭概念”的区分。
- 产业链结构适合教学。
- 后续能和 radar 证据链结合。

## P0 交付标准

P0 不要求内容全。

P0 要证明流程能跑通：

- 产业列表能打开。
- 单个产业页能展示统一布局。
- 图谱节点可以点击。
- 右侧能展示节点解释。
- 公司角色表能展示候选公司和证据状态。
- 自定义内容块能插入。
- 页面文案保持研究/学习口径，不出现投资建议。

建议 P0 先只做 1 到 2 个产业页面。

例如：

```text
AI 算力液冷
CPO/光通信
```

## 分阶段路线

### Phase 0：文档和内容模板

目标：

- 定义页面结构。
- 定义内容 schema。
- 写 1 个产业样例内容。

产物：

- 本文档。
- 内容模板。
- `AI 算力液冷` 样例数据。

### Phase 1：静态产业页

目标：

- 新增 `产业链` Tab。
- 用本地内容文件渲染页面。
- 做统一图谱和详情组件。

不接：

- 消息系统。
- AI 抽屉。
- 自动更新。

### Phase 2：内容生产流程

目标：

- 扩展到 5 到 10 个产业。
- 打磨内容模板。
- 建立证据引用规范。
- 形成 Codex 调研、总结、写入、复核的标准流程。

这一阶段仍然不建设自动化离线任务。

每个产业按同一套人工主导流程推进：

```text
确定产业范围
  -> Codex 拉取公开资料和市场讨论
  -> 提炼稳定产业链结构
  -> 标记关键卡点和误判风险
  -> 整理 A 股公司角色
  -> 写入统一内容文件
  -> 用户审阅和二次打磨
```

这里的效率来自：

- 页面结构固定。
- 内容 schema 固定。
- 证据口径固定。
- Codex 可以重复执行同一套研究和编辑动作。

不是来自爬虫、定时任务或全自动生成。

### Phase 3：消息挂载

目标：

- 把现有消息、主题、个股证据链挂到产业节点。
- 每个产业页出现“最近变化”。
- 不改变基础产业结构，只追加动态信号。

### Phase 4：AI 抽屉

目标：

- 针对当前产业页问答。
- 针对当前节点解释。
- 针对证据缺口提出补全建议。
- 支持受控内容编辑。

## 内容质量原则

每个产业页必须遵守：

- 先讲产业逻辑，再讲股票。
- 先讲卡点，再讲受益。
- 先讲风险，再讲机会。
- 不把概念相关当成真受益。
- 不把模型推断当成事实。
- 缺收入占比、订单、客户、量产证据时，只能写 candidate。
- 所有公司角色都要能回到证据来源。

页面最终要训练用户问这些问题：

```text
这个需求真的发生了吗？
哪个节点最紧？
这个节点为什么难扩张？
A 股公司是否真的在这个节点？
收入和利润能不能传导？
市场是不是已经过度定价？
什么证据会推翻这条逻辑？
```

## 当前技术判断

这个方案比“全自动图谱”明显更容易。

原因：

- 不需要第一阶段解决全量数据自动抽取。
- 不需要复杂图数据库。
- 不需要实时消息匹配。
- 不需要让 AI 自动维护事实。
- 页面结构统一，内容可以逐个产业打磨。

真正的成本从工程难度转移到内容质量。

这是可控的。

## 最重要的取舍

不要把第一版做成：

```text
产业链百科大全
```

要做成：

```text
少数高质量产业链学习页
```

等这套结构被验证后，再扩到 20 个、50 个、100 个产业。
