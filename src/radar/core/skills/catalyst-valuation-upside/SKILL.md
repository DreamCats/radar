# 催化估值线索空间测算

用于把一份 Radar 催化估值线索报告二次加工成“还有多少空间、是否已经定价、下一步盯什么”的研究任务。默认假设报告中的原文证据可能成立，但必须把已确认事实、基于假设的推断、仍需验证的条件分开。

## 工作流

1. 先从页面上下文获取 `report_id`，调用 `radar_get_catalyst_valuation_report` 读取本地结构化报告。不要依赖公网报告 URL 抓网页正文。
2. 对每个标的先补当前市值数据：优先用 `radar_get_stock_price_history` 查询 `daily_basic` 最近交易日的 `total_mv`，必要时用 `radar_get_realtime_quote` 补盘中价格和涨跌幅。查不到就标“当前市值缺口”，不要编造；但仍要完成定性状态和数据缺口说明。
3. 需要验证收入、归母净利、现金流、资产负债、ROE、毛利率和增长质量时，调用 `radar_get_stock_financials`。
4. 需要验证业绩预告、业绩快报、主营业务构成、分部收入或业务暴露时，调用 `radar_get_stock_forecast_or_segments`。
5. 需要把报告原文转述升级为公告/交易所/互动平台证据时，调用 `radar_search_stock_disclosures`；查不到不代表不能测算，但必须保持“报告原文转述/线索假设”，不要写成已确认事实。
6. 从报告证据和补充工具结果中抽取目标市值、利润、产能、价格、PE、市占率、订单、渗透率等核心数字。
7. 用第一性原理重算目标市值区间：资源品优先用“产能 x 价差 x 净利率 x PE”，制造/电子优先用“收入 x 净利率 x PE”，平台型公司按业务分部加总。
8. 如果报告没有给足正向估值所需的收入、利润、产能、价格或 PE/PS 锚，不要写“待补”后结束；必须做反推测算：基于当前市值和已有 PE/PS/利润线索，反推要达到 30%/80% 空间分别需要多少利润、收入、订单或估值倍数，并说明这些假设是否被原文证据支撑。
9. 计算剩余空间：`(目标市值 / 当前市值 - 1) x 100%`。区间目标必须给区间空间；无法形成正向目标区间时，空间列写“无可靠正向锚”，并在拆解里给反推结果。
10. 判断定价状态：`显著空间`、`有空间但需验证`、`基本反映`、`已超目标`、`严重透支`。不要输出“待补”“待补市值后排序”作为状态。
11. 做交叉验证：同一标的如果在多份报告或多条证据中重复出现，提升跟踪优先级；如果只有单条小作文，降低置信度。
12. 给每一行补充 `锚类型 / 证据等级 / 缺口原因 / 通知等级`。通知等级只允许：`可通知`、`条件触发`、`仅入库不通知`。
13. 输出机会排序，不输出买卖、仓位、确定性收益或“必涨”措辞。

```text
## 重点标的拆解
每个报告标的都必须覆盖，不能只写“重点标的”。每个标的按：
- 第一性原理公式
- 关键数字来源
- 当前市值对比
- 正向目标区间或反推隐含要求
- 触发升级条件
- 触发降级条件

## 已充分定价或追高风险
列出当前市值已经接近或超过目标市值的标的，并说明为什么不应只看故事热度。

## 数据缺口
列出没有查到当前市值、目标市值口径不清、证据等级偏低、产业链假设无法转译为利润或疑似误命中的地方。
```

## 判定规则

- 剩余空间 >= 80% 且核心数字可交叉验证：`显著空间`。
- 剩余空间 30%-80%：`有空间但需验证`。
- 剩余空间 0%-30%：`基本反映`。
- 当前市值超过目标区间上沿：`已超目标`。
- 当前市值超过目标区间上沿 100% 以上：`严重透支`。
- 如果当前市值缺失，不给空间百分比，但仍用证据质量和估值锚完整度给状态，不写“待补市值后排序”。
- 如果没有目标市值、利润或收入锚，不能进入“可测算机会排序”的前列；放入“高赔率但证据薄 / 无可靠正向锚”分组，并用反推隐含要求说明需要补哪些事实。
- 单条小作文、新闻转载、行业验证节点，不能单独支撑 `显著空间`；除非能补到公司层面订单、利润、收入或产能转译。
- `锚类型` 可用：券商目标价、券商利润PE、产业链假设、反推测算、无锚、误命中。
- `证据等级` 可用：公告确认、券商预测、产业链线索、社群转述、误命中。可以组合，例如 `券商预测+公告存在`。
- `缺口原因` 写最短可审计原因，例如：缺目标PE、缺利润预测、缺订单价格、缺产能转收入、空间下沿不足、误命中。
- `通知等级` 判定：空间明确且证据至少有券商预测或多源线索时写 `可通知`；空间下沿不足、兑现条件强或早期产业链线索写 `条件触发`；无可靠锚、误命中或明显已充分定价写 `仅入库不通知`。

## 约束

- 报告 URL 只作为给人打开的参考链接；分析输入以 `radar_get_catalyst_valuation_report` 返回的本地结构化报告为准。
- 不把“目标市值”写成投资建议；所有目标都必须注明“证据成立假设下”。
- 不把短期涨跌幅当作空间测算主因；涨跌幅只用于判断是否已经被市场快速消化。
- 不为了补齐表格而捏造当前市值、PE 或利润率。
- 不把没有单位的数字直接当作亿元或万吨；单位不清要列入数据缺口。
- “已确认事实”只写工具实际返回的数据、公司公告或可验证公开来源；报告原文和券商/社群转述必须标为“报告原文转述”或“线索假设”，不要混入已确认事实。
