# 策略文档

这个目录用来沉淀 radar 的策略能力。

这里说的“策略”不是完整交易策略，也不是自动买卖系统。它更像投资人每天打开工作台时的注意力排序器：用微信消息、原始证据链、行情反馈和 LLM 逻辑梳理，回答“今天先看什么、为什么值得看、下一步应该深挖哪里”。

## 当前策略

- [个股证据链生命周期策略](./stock-evidence-chain-lifecycle.md)：当前优先设计方向。它以当天新增消息里的股票为入口，倒查最近 40 天原始证据链，再让 LLM 判断阶段和逻辑。
- [早期概念雷达策略](./early-concept-radar-strategy.md)：优先研究的新策略，目标是在概念刚被提出、还没有充分发酵时，提前锁定概念和首次绑定个股。
- [发酵确认策略](./opportunity-signal-strategy.md)：原“机会信号策略”，现在降级为确认层。它负责判断已经升温的方向是否仍值得看，不能单独解决追高风险。

## 当前优先级

radar 后续策略不做纯技术面，也不追公开已知消息。核心是消息面和证据链，技术面只作为位置、涨幅、回撤和过热过滤。

第一优先级调整为验证“个股证据链生命周期”：本地计算只负责找证据，LLM 负责讲清逻辑、判断阶段，并且每个标签都能反查原始消息。

当前先做后端/CLI，不做 WebUI。旧的 anchor 共现、叙事快照、股票绑定离线任务不再作为优先实现方向；废弃表清理必须显式执行，不跟随普通启动自动删除。

## 后续新增策略怎么写

每个策略单独一份文档，至少讲清楚：

- 它站在投资人视角解决什么问题。
- 它的核心判断思路是什么。
- 它使用哪些现有离线产物，是否需要新的 LLM 流程。
- 它输出什么，投资人打开网站后应该怎么用。
- 它不解决什么，避免被误用成买卖建议。

先把这些问题讲清楚，再决定是否实现 UI 或新增离线任务。
