# 01 · 数据源调研：微信投研群消息

## 来源

老板给的微信数据源。通过一个 HTTP API 拉取个人微信的**私聊**和**群消息**。
本地已有历史落盘数据：`~/.config/stock-news/data/<YYYY-MM-DD>/raw/`。

> ⚠️ 这是 stock-news（公司项目）的数据目录。radar 应使用自己独立的数据目录，
> 不要污染 / 依赖老项目的落盘路径。但数据**结构**和 **API** 可直接复用。

## API

来自 `stock-news/src/stock_news/common/wechat_api.py`，极简：

```
GET <base_url>?name=<source>&starttime=<start>&endtime=<end>
```

- `name`：`个人消息`（私聊）或 `个人群`（群消息）
- `starttime` / `endtime`：`yyyyMMddHHmmss`
- 返回：JSON 数组，每项字段为中文：`发送人` / `时间`(`%Y-%m-%d %H:%M:%S`) / `内容` / `群名称`(可选)
- 无鉴权头（base_url 本身即入口），httpx GET 即可

## 落盘文件命名

```
个人消息_<起yyyyMMddHHmmss>_<止yyyyMMddHHmmss>.json   # 私聊
个人群_<起>_<止>.json                                   # 群消息
```

一天内可能有多个时间窗切片文件（增量拉取，按 fetch_window 切）。

## 单条消息结构（落盘后 / RawMessage）

```json
{
  "source": "个人群",
  "sender": "戴清@长江策略",
  "message_time": "2026-05-30T00:05:26",
  "raw_content": "长江证券中期策略会定位光谷……",
  "group_name": "长江策略VIP群",
  "fetch_time": "2026-05-30T13:05:07.538113",
  "fetch_window": "20260530000000-20260530005959",
  "message_id": "79b03cf431b67363"
}
```

字段说明：
- `source` — `个人群` / `个人消息`
- `sender` — 发送人，常带后缀如 `戴清@长江策略`、`陈果 东方财富策略`（可提取「机构/角色」）
- `group_name` — 群名（私聊为 null）
- `message_id` — 去重主键
- `fetch_window` — 该条所属的拉取时间窗

## 数据画像（基于 2026-05-30 群消息样本，199 条）

### 真投研信号（高价值）
- **券商策略观点**：陈果（东财策略）、长江策略、华泰政策、富国长江研究
- **产业链情报**：华工科技 TGV 玻璃通孔装备、车用固态电池国标、三星 HBM4E 样品
- **个股/IPO 异动**：MiniMax 启动 A 股 IPO
- 大量带机构抬头的研究内容，天然适合做「来源可信度」加权

### 噪音（需狠狠过滤）
样本里混着大量与投研无关的群：
- `小学反馈群`（英语作业、背诵讲义）
- `祝福你` 群
- 各种生活/社交群

> 启示：radar 必须有**群白名单 / 黑名单**机制。个人版可以更激进——
> 只订阅我手工挑选的高质量投研群，其余一律不入库。

## 对 radar 的直接启示

1. **API/结构零成本复用** — 拉取逻辑很简单，radar 可独立实现一份精简版。
2. **群白名单是第一道降噪闸** — 个人版应在「入库前」就过滤掉非投研群。
3. **sender 抬头含机构信息** — 可解析出「机构来源」做可信度/胜率维度。
4. **message_id 去重** — 多时间窗切片会重叠，必须按 message_id 去重。
5. **独立数据目录** — radar 用自己的落盘路径（如 `~/.config/radar/` 或项目内 `data/`），与 stock-news 隔离。
