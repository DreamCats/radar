# radar 个股证据链产品复盘和改造计划

本文回答两个问题：

1. 现在 radar 的个股证据链还缺什么？
2. 怎么把它从“看板”升级成“帮 Maifeng 学会老板判断方式的工作台”？

## 当前结论

radar 已经有很好的底层材料：

- 能从微信消息里抽取个股提及。
- 能按发送人、会话、消息指纹做扩散统计。
- 能让 LLM 输出阶段、原因、证据时间线、风险和下一步观察点。
- 能接入本地 Tushare 日线缓存，把行情点放进判断。
- 前端已经有个股证据链列表、阶段筛选、详情、K 线抽屉和 AI 问答入口。

但它现在更像：

```text
结果展示页
```

还不像：

```text
训练用户判断力的学习工作台
```

对小白来说，最大问题不是“没有数据”，而是：

```text
我看到了阶段，但我不知道这个阶段是怎么从消息一步步推出来的。
我看到了 K 线，但我不知道它是在验证消息，还是在否定消息。
```

## 当前代码里的真实现状

本次产品分析主要看了这些当前代码：

| 范围 | 文件 | 看到什么 |
| --- | --- | --- |
| 流水线编排 | `src/radar/core/usecases/stock_evidence_chain/pipeline.py` | 拉消息、建候选、取行情、调用 LLM、保存判断的主流程 |
| 股票识别和证据打分 | `src/radar/core/usecases/stock_evidence_chain/matcher.py` | 把原始消息里的股票和调研、催化、研报、强推、价格等证据类型识别出来 |
| 候选池和证据包 | `src/radar/core/usecases/stock_evidence_chain/storage.py` | 消息按股票聚合，按去重触发、发送人、会话和强证据进入候选池 |
| 行情验证 | `src/radar/core/usecases/stock_evidence_chain/market.py` | 从本地日线缓存取行情点，计算区间收益、回撤、量能等市场证据 |
| 阶段判断 | `src/radar/core/usecases/stock_evidence_chain/llm.py` | 阶段口径、LLM 输出 schema、市场证据约束都在这里 |
| 看板视图 | `src/radar/core/usecases/stock_evidence_chain/views.py` | 返回阶段、原因、证据链、市场点，并按可行动优先级排序 |

| API 客户端和类型 | `web/ui/src/api/radarApi.ts`、`web/ui/src/types/strategy.ts` | 前端只消费最新证据链和 K 线，还没有历史/学习案例接口 |
| 策略页 | `web/ui/src/pages/StrategyPage.tsx` | 当前只展示最新一版个股证据链 |
| 证据链面板 | `web/ui/src/components/StockEvidenceChainPanel.tsx` | 已展示阶段筛选、证据时间线、市场证据、风险、下一步 |
| K 线抽屉 | `web/ui/src/components/StrategyStockDrawer.tsx` | 已有 K 线和指标，但还没有事件标注和阶段轨迹 |

### 已有能力

后端：

- `src/radar/core/usecases/stock_evidence_chain/storage.py`
  - 候选池按消息窗口聚合。
  - `unique_trigger_count >= 7` 会进入热度通道。
  - `unique_trigger_count >= 3`、`sender_count >= 2`、`conversation_count >= 2` 且有强证据时，会进入早期强信号通道。
- `src/radar/core/usecases/stock_evidence_chain/llm.py`
  - 阶段包括线索、种子、论证、扩散、定价、拥挤。
  - Prompt 明确要求 pricing 必须结合市场证据。
  - Prompt 明确要求 crowded 必须结合市场证据和讨论证据。
- `src/radar/core/usecases/stock_evidence_chain/views.py`
  - 返回阶段、置信度、触发数、去重数、发送人数、会话数、证据链、市场摘要、市场点。
  - 当前排序会优先看种子、论证、线索和早扩散，涨幅过大或拥挤会后置。
- `src/radar/web/server/routers/strategy.py`
  - 已有 `/api/strategy/evidence-chain/latest`。
  - 已有 `/api/strategy/stocks/{ts_code}/chart`。
  - 已有启动个股证据链作业的接口。

前端：

- `web/ui/src/pages/StrategyPage.tsx`
  - 当前只有一个策略模式：个股证据链。
  - 只拉最新一版 `fetchStockEvidenceChainLatest({ limit: 120 })`。
- `web/ui/src/components/StockEvidenceChainPanel.tsx`
  - 展示候选股票、观察池、正在定价、拥挤风险。
  - 支持按阶段筛选。
  - 详情展示阶段原因、证据时间线、市场证据、定价风险、拥挤风险、下一步盯什么。
  - AI 入口已经有不错的问题模板。
- `web/ui/src/components/StrategyStockDrawer.tsx`
  - 支持打开 K 线。
  - 展示区间收益、高点回撤、置信度和证据摘要。

这些能力说明：数据底座不是主要短板。

短板在产品表达和学习闭环。

## 主要不足

### 1. 只有最新快照，没有阶段演进

现在接口只返回最新一版判断。

用户能看到：

```text
这只股票现在是扩散期。
```

但看不到：

```text
它昨天是不是种子期？
它什么时候从论证期变成扩散期？
价格是在阶段变化前涨，还是阶段变化后涨？
```

这会导致用户学不到“老板脑子里的时间感”。

投资判断很大一部分是时间顺序：

```text
先有产业催化
再有调研和报告
再多人扩散
再价格放量
再出现拥挤或兑现
```

如果 radar 只展示最后结果，就很难训练这种判断。

### 2. 原始消息到证据类型的抽象链不够直观

现在详情里有证据时间线，也会展示 `raw_content` 或 LLM 摘要。

但对小白来说，还缺中间层：

```text
这句话为什么算催化？
这句话为什么算调研？
这句话为什么只算噪音？
```

现在页面更像把结论给用户，而不是教用户怎么推理。

小白需要看到：

```text
原始消息 -> 证据标签 -> 阶段贡献 -> 需要验证什么
```

例如：

| 原始消息类型 | 证据标签 | 对阶段的贡献 | 还缺什么 |
| --- | --- | --- | --- |
| 公司调研纪要 | 调研 | 说明有人研究 | 还缺产业催化和价格确认 |
| 提价 / 缺货 | 催化 | 可能影响利润 | 还缺公司受益路径 |
| 多家强推 | 扩散 | 说明逻辑传播 | 还缺是否已定价 |
| 放量大涨 | 市场验证 | 说明资金认可 | 还缺是否过热 |

### 3. 市场验证和消息证据还是分开的

现在有市场点，也有 K 线抽屉。

但它们还没有形成一张“验证图”：

```text
哪一天出现关键消息？
那天之前价格怎样？
那天之后 1/3/5/10 日怎样？
成交量有没有变？
阶段判断有没有变化？
```

结果是用户会看到 K 线，但不知道该看哪里。

对小白来说，K 线应该被标注成：

- 第一条调研消息。
- 第一条产业催化。
- 第一条强推。
- 多人多群扩散开始。
- 第一次放量。
- 阶段从论证到扩散。
- 阶段从扩散到定价。
- 大回撤或证伪。

这样他才知道消息和价格之间的关系。

### 4. 没有“今天相比昨天发生了什么”

LLM 输出里已经有 `incremental`，但产品上还没有把它变成主视角。

真正有价值的问题是：

```text
今天新增了什么证据？
阶段为什么变了？
是消息变了，还是价格变了？
```

如果每天 3000 到 5000 条消息，用户不可能自己读完。

radar 应该优先告诉用户：

- 哪些股票从种子期进入论证期。
- 哪些从论证期进入扩散期。
- 哪些从扩散期进入定价期。
- 哪些消息很多但价格不认。
- 哪些价格涨了但消息没有新增事实。

这比单纯榜单更有价值。

### 5. `自己发` 还没有被产品化

用户提到可以搜老板自己的聊天记录，`sender: "自己发"`。

但要注意：

```text
自己发不是买卖记录。
自己发更适合当成关注痕迹。
```

产品上可以把它叫：

```text
关键关注痕迹
```

而不是：

```text
老板买入信号
```

它能帮助回答：

- 老板什么时候第一次主动转发或提到这只股票？
- 当时这只股票处于什么阶段？
- 后面阶段有没有继续推进？
- 后面价格有没有验证？
- 老板关注的是个股，还是背后的产业叙事？

这个功能对学习很重要，因为它能把“老板的注意力”从海量消息里抽出来。

但合规和认知边界也要写清楚：

- 不推断真实交易。
- 不输出确定性收益。
- 不把聊天记录包装成荐股。
- 只用于个人复盘和学习。

### 6. 缺少反证和失败案例

现在页面天然更容易展示“有证据的股票”。

但学习投资，失败案例更重要。

例如这批 50 个案例里，很多股票有调研、报告和扩散，但市场验证是负的。

这些案例应该被单独标出来：

```text
消息强，但价格不认
```

小白必须学会：

```text
证据链不是越长越好。
如果价格长期不认，或者跌幅很大，说明逻辑可能被证伪、被延后，或者市场有更大的担忧。
```

### 7. 现在按股票聚合，还没有叙事生命周期

老板真正看的往往不是单只股票。

他可能先看到：

```text
AI 服务器供需
MLCC 涨价
半导体设备国产替代
海风订单周期
保险估值修复
```

然后再看哪些股票参与这条叙事。

当前 radar 主要是：

```text
股票 -> 阶段
```

长期应该升级到：

```text
叙事 -> 生命周期
股票 -> 在这条叙事里的参与状态
```

否则会混淆两件事：

- 这只股票本身有没有消息。
- 这只股票是不是当前主叙事里的核心受益者。

### 8. 缺少政策主题和机构认可层

当前个股证据链主要回答：

```text
这只股票的消息证据到了哪个阶段？
```

但 A 股里还必须回答：

```text
这条叙事是不是政策顺风？
它是不是机构愿意抱的主线？
其他机构有没有开始确认？
它是主线核心，还是边缘跟风？
```

如果少了这一层，就会出现一个困惑：

```text
为什么叙事逻辑讲得通，但市场不认可？
```

产品上应该把个股证据链拆成四个分数：

| 分数 | 回答的问题 | 可能的数据 |
| --- | --- | --- |
| 证据链阶段 | 故事有没有形成、扩散、定价 | 消息、发送人、会话、证据类型、LLM 阶段 |
| 政策顺风度 | 是否符合国家当前想扶的方向 | 政策关键词、主题标签、政策文件、监管表态 |
| 机构认可度 | 其他资金有没有一起确认 | 研报扩散、调研机构、行业指数、成交额、ETF/基金持仓、龙虎榜、融资融券 |
| 定价程度 | 预期是否已经反映在价格里 | 区间涨幅、回撤、量能、相对行业强弱 |

这层很重要，因为：

```text
政策顺风是入场券。
机构认可是定价权。
价格位置决定性价比。
```

短期可以先做轻量版：

- 手工维护政策主题词表：新质生产力、人工智能+、集成电路、机器人、低空经济、设备更新、反内卷、稳股市等。
- 给每只股票打主题标签：AI 算力、半导体、机器人、新能源旧主线、金融稳市场、医药外部风险等。
- 增加“为什么市场不认”字段：过剩、价格战、老共识、外部风险、非核心票、已充分定价。
- 在详情里展示“政策顺风但未获市场确认”或“市场已确认但位置偏高”。

具体落地方案见：

```text
docs/learn/market-recognition-chain-landing-plan.md
```

这份文档的核心原则是：第一版不要靠大模型直接打“认可度”，而是先做“证据槽位 + 可解释规则 + 缺口提示”。

## 建议的产品形态

### 页面 1：今日学习

目标不是让用户看完 120 只股票。

目标是每天只吃透 3 到 5 个案例。

每个案例按这个结构展示：

```text
1. 原始消息
2. radar 抽象成了什么证据
3. 为什么判断为当前阶段
4. 市场是否验证
5. 如果我是老板，我会继续盯什么
6. 这个案例教会我什么
```

案例类型要混合：

- 一个早期机会。
- 一个扩散但未验证。
- 一个已经定价。
- 一个消息很强但失败。
- 一个老板关注痕迹。

这样用户每天都能训练判断力。

### 页面 2：阶段变化

核心视图：

```text
股票 | 昨天阶段 | 今天阶段 | 变化原因 | 价格验证 | 下一步
```

优先展示：

- 种子 -> 论证。
- 论证 -> 扩散。
- 扩散 -> 定价。
- 定价 -> 回撤。
- 热度上升但价格不认。

这比“最新列表”更接近老板每天看消息时脑子里的动作。

### 页面 3：证据链阅读器

把一只股票拆成四列：

| 原始消息 | 证据类型 | 阶段贡献 | 还要验证 |
| --- | --- | --- | --- |
| 某调研/纪要 | 调研 | 有人研究 | 产业催化 |
| 提价/缺货 | 催化 | 影响利润 | 公司受益比例 |
| 多家强推 | 扩散 | 传播加速 | 是否已经定价 |
| 放量上涨 | 市场验证 | 资金认可 | 是否过热 |

这页的作用是教用户“怎么读消息”，不是只给结论。

### 页面 4：K 线验证图

K 线不应该只是普通行情图。

它应该带事件标注：

- 关键消息点。
- 阶段切换点。
- 成交放大点。
- 首次强推点。
- `自己发` 关注点。
- 回撤或证伪点。

用户点一个标记，就能看到对应消息摘要和阶段贡献。

### 页面 5：老板关注复盘

这个页面只回答一件事：

```text
自己发 的消息，通常出现在生命周期哪一段？
```

不要做成“老板买卖记录”。

应该做成：

| 股票/叙事 | 自己发时间 | 当时阶段 | 后续阶段 | 后续价格 | 学习结论 |
| --- | --- | --- | --- | --- | --- |
| 某票 | T0 | 论证期 | T+3 扩散 | +X% | 关注早于扩散 |
| 某票 | T0 | 定价期 | T+5 回撤 | -X% | 关注偏复盘或风控 |

这能帮助你学：

```text
老板什么时候是在找机会，什么时候是在确认，什么时候是在提醒风险。
```

### 页面 6：政策主题地图

这个页面回答：

```text
当前市场资金在围绕哪些政策主题定价？
每只股票在主题里是核心、弹性、补涨，还是噪音？
```

建议先做一个很薄的版本：

| 主题 | 政策方向 | 相关股票 | 证据阶段 | 市场验证 | 机构认可 | 风险 |
| --- | --- | --- | --- | --- | --- | --- |
| AI 算力 | 新质生产力 / 人工智能+ | 海光信息、天孚通信、长飞光纤 | 扩散 / 定价 | 强弱分化 | 看研报和成交 | 估值、外部限制 |
| 半导体设备 | 集成电路 / 自主可控 | 中微公司、华海清科、长川科技 | 定价 / 回撤 | 有分化 | 看订单和客户验证 | 已定价、兑现压力 |
| 新能源旧主线 | 双碳 / 未来能源 | 宁德时代、恩捷股份、星源材质 | 论证 / 扩散 | 偏弱 | 看供需出清 | 过剩、价格战 |

这个页面的作用不是预测国家队买什么，而是让用户看到：

```text
国家政策方向、机构偏好、个股证据链、价格验证是不是在同一个方向上。
```

## ROI 优先级

### P0：阶段变化和今日学习

优先做。

原因：

- 最直接服务 Maifeng 自己学习。
- 不需要新数据源。
- 可以复用现有 `stock_lifecycle_judgements`。
- 能立刻把 radar 从看板变成学习工具。

建议交付：

- 后端增加历史快照列表。
- 后端增加单只股票生命周期查询。
- 前端增加“今日学习 3 个案例”。
- 前端增加“阶段变化”列表。

收益：

```text
每天不用看 3000 条消息，只看最值得学习的几个阶段变化。
```

### P1：K 线事件标注

第二优先级。

原因：

- 小白最缺的是把消息和价格连起来。
- 当前已有 K 线接口和市场点，改造成本可控。
- 能显著提升“看懂证据链”的体验。

建议交付：

- 在 K 线图上标注关键消息日期。
- 标注阶段切换日期。
- 标注第一次强推、第一次扩散、第一次价格验证。
- 鼠标悬停展示对应消息摘要。

收益：

```text
用户能直观看到消息到底领先价格、同步价格，还是落后价格。
```

### P1：原始消息到证据类型的阅读器

和 K 线事件标注同级。

原因：

- 这是训练判断力的核心。
- 当前后端已经能返回 `raw_content`、`evidence_chain`、`family_counts`。
- 主要是产品表达问题。

建议交付：

- 每条关键证据显示“为什么被归类为调研/催化/扩散/价格”。
- 每条证据显示它对阶段判断的贡献。
- 每条证据显示还缺什么验证。

收益：

```text
用户从“看结论”变成“学推理”。
```

### P2：自己发关注痕迹

第三优先级。

原因：

- 用户明确提到老板自己的聊天记录。
- 对学习老板判断方式很有价值。
- 但需要谨慎命名，不能暗示交易。

建议交付：

- 支持筛选 `sender = "自己发"`。
- 在证据链里标注“关键关注痕迹”。
- 统计自己发出现在阶段的分布。
- 对比自己发之后的阶段变化和价格变化。

收益：

```text
把老板注意力从海量消息里显性化。
```

### P2：失败案例和反证库

第三优先级。

原因：

- 小白最容易只看成功案例。
- 失败案例能快速降低追高和迷信消息的概率。

建议交付：

- 自动标记“消息强但价格不认”。
- 自动标记“定价后大回撤”。
- 自动标记“扩散后没有新增证据”。
- 每天推 1 个反面案例学习。

收益：

```text
让 radar 不只是找机会，也能训练避坑能力。
```

### P2：政策主题和机构认可层

第三优先级，但应该尽快进入设计。

原因：

- 它解释了“消息逻辑通但市场不认”的核心问题。
- 它能把个股消息从小故事提升到市场主线。
- 它能避免用户只看微信群热度，忽略政策方向、机构偏好和定价位置。

建议交付：

- 给个股证据链增加主题标签。
- 增加政策顺风/逆风字段。
- 增加机构认可度解释。
- 增加“市场为什么不认”的反证标签。
- 在今日学习里加入“政策顺风但市场不认”的案例。

收益：

```text
用户不只学会读消息，还能学会站在机构和政策资金的视角读市场。
```

落地边界：

```text
P2 不是做一个神秘的机构认可模型。
P2 是先把认可拆成政策、产业、机构讨论、资金、定价、反证几个可验证槽位。
```

第一版只用现有消息和行情数据做保守判断；缺失的数据必须显示 unknown。

主题映射不应该优先靠全量人工文件。当前 radar 已有 `market_anchors` / `market_anchor_members`，可以复用 Tushare 的东财概念、同花顺/申万行业和题材数据作为主数据。人工只做少量 override：补缺失、纠错、选择当前主叙事和角色。

等行业指数、资金流、龙虎榜等数据接入后，再逐步增强。

### P3：叙事生命周期

后做。

原因：

- 这是更正确的长期方向。
- 但需要更复杂的主题归并、股票参与度、主线/补涨识别。
- 现在先把个股证据链打磨好更划算。

建议交付：

- 从消息中抽叙事主题。
- 建叙事阶段：线索、论证、扩散、定价、拥挤、兑现、衰减。
- 每只股票标注在叙事里的角色：核心、弹性、补涨、跟随、噪音。

收益：

```text
从“看个股”升级为“看市场主线”。
```

## 推荐实施顺序

### 第一周：先做可回放

目标：

```text
让用户能看到阶段怎么变。
```

后端：

- 增加 `list_stock_evidence_chain_snapshots()`。
- 增加 `get_stock_evidence_chain_at(as_of_time)`。
- 增加 `get_stock_lifecycle(ts_code)`。
- 暴露 `/api/strategy/evidence-chain/snapshots`。
- 暴露 `/api/strategy/evidence-chain/history/{ts_code}`。

前端：

- 在策略页增加日期选择。
- 在抽屉里增加阶段轨迹。
- 在列表里展示“较上次变化”。

验收：

- 能选择任意一次 `as_of_time` 看当时榜单。
- 点进一只股票能看到阶段变化时间线。

### 第二周：做今日学习

目标：

```text
每天自动挑 3 到 5 个最值得学习的案例。
```

案例选择规则：

- 1 个早期但证据不错的案例。
- 1 个扩散但价格不认的案例。
- 1 个消息和价格共振的案例。
- 1 个定价后回撤或失败案例。
- 如果有 `自己发`，优先放一个关注痕迹案例。

验收：

- 用户打开策略页，第一屏就能看到今日学习卡片。
- 每张卡能解释“为什么值得学”。

### 第三周：做 K 线事件标注

目标：

```text
把消息时间线和价格走势合到一张图。
```

验收：

- K 线上能看到关键消息标记。
- 点击标记能看到消息摘要、证据类型、阶段贡献。
- 能区分消息领先、同步、落后价格。

### 第四周：做自己发关注复盘

目标：

```text
把老板关注痕迹变成学习材料。
```

验收：

- 能筛选所有 `sender = "自己发"` 的证据链案例。
- 能看到自己发出现时的阶段和后续价格。
- 页面文案不暗示交易，只叫关注痕迹。

## 数据和模型还要补的字段

短期尽量先复用现有表，不急着大迁移。

但长期建议补这些派生字段：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `stage_changed_from` | 上一次阶段 | 阶段变化列表 |
| `stage_changed_reason` | 阶段变化原因 | 今日学习 |
| `first_seen_time` | 首次进入候选池时间 | 判断早晚 |
| `first_key_evidence_time` | 首条强证据时间 | K 线标注 |
| `first_self_sent_time` | 首次自己发时间 | 关注痕迹 |
| `market_confirmed_time` | 首次市场验证时间 | 消息领先/滞后分析 |
| `outcome_state` | 兑现、证伪、衰减、拥挤 | 复盘 |
| `case_label` | 买点、卖点、避坑、复盘 | 今日学习分发 |

## 不建议现在做的事

短期不要做这些：

- 自动买卖建议。
- 自动交易。
- 复杂回测平台。
- 多用户权限。
- 大而全的策略市场。
- 把老板消息包装成荐股。

原因：

```text
当前最大价值不是替用户下结论，而是帮用户学会怎么读证据链。
```

## 最小可行版本

最小版本只需要完成三件事：

1. 能回放一只股票的阶段变化。
2. 能把原始消息解释成证据类型。
3. 能把关键消息标在 K 线上，看价格是否验证。

只要这三件事做好，radar 就会从：

```text
这只股票是什么阶段
```

升级为：

```text
为什么是这个阶段，我怎么学会这个判断
```

## 最终产品目标

radar 最终不应该只是消息雷达。

它应该是：

```text
个人投资判断训练器
```

它每天帮 Maifeng 做四件事：

1. 从几千条消息里挑出最值得学习的案例。
2. 把原始消息抽象成证据链。
3. 用价格和成交验证证据链。
4. 复盘阶段演进，训练下一次判断。

这才是它服务自己的方式。
